# Dev Tools
These are the tools which can be used when developing this project.

Unless stated otherwise, they're meant to be run in the project's root directory. See each platform's README for more info.

## Audits that back a claim in the knowledge base (`%USERPROFILE%\knowledge\projects\hachimi-edge\defects\`)

| Tool | What it prints |
|---|---|
| `python tools/scan_hook_barriers.py` | For every hook boundary `new_hook!` arms, which barrier macro or guard call stands on it and which answer that arm gives a `Panicked` trip, with the totals adding up to the population it walked. Walks the same arming population once more for the `disabled_hooks` key (C27), reading the rule out of `src/il2cpp/hook/mod.rs` instead of keeping its own copy of it: the id expression `new_hook!` builds and the prefix `hook_id` cuts, each printed with the line it was read at, every comparison the decision function makes between a configured key and a hook id, the second copy of the same rule that the report after hooking runs on and whether it agrees with the arming decision, the population every bare wrapper name in the tree reaches under those comparisons against the population `disabled_hooks.contains(stringify!($hook))` reached, and both fixtures the Rust tests are built from (`COLLIDING_KEYS`, `SINGLE_NAME_KEYS`) compared with the population the tree arms now. A comparison it cannot read is a row, not a silence: a rule rewritten out of this tool's model fails the audit. It attests the decision and the population, never the behaviour - `cargo test --lib` is what calls `hook_is_disabled`. Ends with the committability section: what `git status --porcelain -uall` reports for this change set and whether a `git add -u` or `git commit -am` commit would silently drop a file the build or an audit needs. Exit 1 while it would, while two arming sites share one key, while the shipped rule reaches a different population than the rule it replaced, while the decision in `hook/mod.rs` is written in a shape the audit cannot read, or while a test's fixture no longer matches the tree. |
| `python tools/check_proxy_export_stubs.py [dll ...] [--call]` | For the linked cdylib (C1): whether the export table carries exactly the names `src/windows/proxy/exports.def` advertises, whether every one of those stubs reads its cell, tests it, branches on an empty cell and only then jumps to what the cell names - with the refusal arm checked for the shadow space, for handing the refusal the same cell it reads, and for answering 0 - and whether any stub still opens with `jmp qword ptr [rip + cell]`, the shape that executes address 0. `--call` maps the file without running `DllMain` and calls every export with every cell unwritten: an inert stub answers 0, a stub that jumps takes `0xC0000005`. Before it reads a file it reads four stubs written out in the script by hand, a guarded arm whose `call` displacement carries a `0a` byte among them; if the rule cannot read those it says so and stops, because a pattern with a bare `.` in a bytes pattern cannot match `0x0a` and once faulted a clean build. A stub it cannot place prints the bytes it was judged on. Exit 1 while any of that is not true. |
| `python tools/scan_extern_c_mutex.py src --transitive` | Every `extern "C"` frame under `src/` (hand written, `def_detour!`, or written by a helper macro), split shipped / `#[cfg(test)]`, and the `unwrap()` / `expect()` calls on a shared lock written inside one. `--transitive` adds the frames that reach such an acquirer through a same-crate helper. |
| `python tools/check_locale_keys.py [--rev REV]` | For the ten locale files (E1, E2): the keys the source asks for with `t!("...")`, how many each file defines, and how far each is from the union across the ten. It fails while a file defines one key twice, because the later definition is the text a player sees, and while `en.yml` lacks a key the source asks for, because `en.yml` is the file every other locale falls back to and a gap there puts the raw key on the screen in every language. It also reads four shapes by hand before it reads a file: a nested file whose keys include `yes:` and `on:` (YAML 1.1 calls those booleans, and a reader that agrees makes the file look like it is missing them), the same key defined twice, and a key the file does not have. The per-locale gap against the union is printed as a number, not enforced: that backlog is upstream's, whose locale pull requests update a few languages. A key built at runtime is invisible here, so those call sites are counted and printed instead of guessed at. |

Four audits are listed here, in `tools/`, and each belongs in the change set it audits. `target/` is gitignored, so a
script kept under `target/scratch/` is deleted by `cargo clean` and by `git clean -xdf`, and a script that
was never put in git's index is dropped by `git add -u` and by `git commit -am` without either command
saying so. A count quoted from a tool that a commit can lose is not reproducible evidence, so these
scripts travel with the code they check and the barrier audit checks that for them.

## Knowledge history

| Tool | What it does |
|---|---|
| `bash tools/knowledge-snapshot.sh ["what changed"]` | Records `LEDGER.md` in the local history outside this repository. `--log`, `--show [rev]` and `--restore [rev]` read it back. AGENTS.md section 1 has the rules. |
| `bash tools/test_knowledge_snapshot.sh` | The cycle test for that script: it runs it against a throwaway history in `target/scratch/ks-test`, checks that a snapshot records `LEDGER.md` and only `LEDGER.md`, that `--log` and `--show` read the record back, that a deletion is recorded rather than silently skipped, and that `--restore` puts `LEDGER.md` back as it was. Seven checks, and it removes the scratch folder when they pass. |
| `python tools/find_method_owner.py <inventory.txt> <pattern>` | Prints the `### image :: Class` header that owns every method and field line of the static map's `inventory.txt` matching a regular expression. `doors.py` prints a method line without the class it sits under, so four classes carrying `SetMarkerVisible` read as one door; this names the owner, which is what decides whether a door is a body a trampoline can patch (ledger item 118). |

The OKF bundle is not in this repository and not this script's job. It lives at
`%USERPROFILE%\knowledge\projects\hachimi-edge\` as a folder of a git-tracked knowledge base with its own
history, indexes and log, and that git versions it. Snapshots taken before the 2026-10-13 move also hold a
`knowledge/` tree; they keep it, and the script says so and leaves it alone. See
`knowledge-history-handoff.md` at the project root (gitignored, and deliberately outside `tools/`, because the
barrier audit reads what a `git add -u` commit would drop out of what lies here).
